# TER v3.1 — Notification & Monitoring Center

Cette version ajoute une couche de monitoring déterministe au-dessus des moteurs existants.

## Routes
- `#/notifications`
- `GET /api/notifications`
- `POST /api/notifications/read-all`
- `POST /api/notifications/:id/read`
- `GET /api/monitoring/status`

## Règles
Le moteur surveille les alertes actives, les signaux forts sur watchlist, les variations inhabituelles et les données live dégradées. Les événements sont dédupliqués pendant 15 minutes pour éviter le bruit.

Les notifications restent en mémoire dans cette version. L'architecture pourra ensuite être reliée à email, webhook ou push via un fournisseur dédié.
